# 42號義麵店 - 開發者交接手冊 (AGENTS.md)

## 1. 空間導航邏輯
- **雙重感應區**：所有空間跳轉必須同時更新 `drawNavigationArrows` (視覺) 與 `getDynamicNavZones` (判定)。
- **滯留時間**：全局統一為 `800ms`。
- **洗手台限制**：
    - 進入：僅限從 KITCHEN 進入。
    - 離開：僅限回到 KITCHEN，且導航箭頭必須位於 **左側**。
- **桌位管理 (Phase 7 更新)**：
    - 接單前必須檢查 `tableStates` 陣列。
    - 客人入座必須綁定 `tableIndex`。
    - **特寫清理模式**：用餐區不再直接執行擦拭，而是透過滯留髒桌子跳轉至 `TABLE_CLEANING` 空間執行。
    - 清理完成後必須將 `tableStates[idx]` 設回 `FREE` 並自動跳轉回 `DINING_ROOM`。
- **雙手並行規範 (Phase 7.1 更新)**：所有互動邏輯必須遍歷 `activeHandPositions`，確保左右手具有對等的操作能力，不可鎖定單一手部。
- **垃圾生成規則**：清理頁面中的物件生成必須基於該桌的紀錄屬性（如 `tableHasDrink`），以維持邏輯一致性。

## 2. 交互區位規範
- **櫃檯 (COUNTER)**：
    - 接單方式：僅限 **微笑接單** (門檻 0.2)，不依賴手部偵測。
    - 提示文字：位於畫面左下角。
    - **阻斷提示**：無空桌時必須顯示警告文字。
- **廚房 (KITCHEN)**：
    - 提示文字：固定於 **左上角** (x:20, y:40-80)。
    - 盤子顯示：當 `cleanPlates === 0` 時隱藏。
- **用餐區 (DINING_ROOM)**：
    - 角色：作為桌位狀態的「概覽中心」與「選擇中心」。
    - 提示：髒桌子上應顯示「停留進入清理」。
- **清理特寫 (TABLE_CLEANING)**：
    - 任務：先撥除垃圾 (`CLEAR_TRASH`)，再執行擦拭 (`WIPE_TABLE`)。
    - **獎勵禁令**：嚴禁在清理過程中給予任何金錢獎勵。
    - **對比度要求**：物理物件（如筷子）配色需考慮背景（如桌面）色調，確保高辨識度。

## 3. 核心規範 (不可違反的準則)
- **解耦偵測邏輯**：臉部（微笑）與手勢（抓取）處理函數必須完全獨立。
- **狀態重置規範**：出餐後必須清空盤子布林值，並將客人轉為 `EATING`。

## 4. 渲染與適配
- **Canvas 解析度**：固定 960x540。
- **UI 避讓**：頂部中央預留給訂單卡片。
