42號義麵店
項目技術與架構說明

這個專案是一款在瀏覽器中執行的互動式餐廳遊戲。玩家用攝影機偵測到的手勢與笑容操作遊戲，單人模式全部在前端完成，線上對戰與排行榜則透過 Firebase 作為後端服務。

一眼看懂 架構流程 前端 後端串聯 檔案分工 如何執行

一眼看懂

專案類型

瀏覽器單頁遊戲

主要入口是 index.html，HTML、CSS、JavaScript 都集中在同一個檔案中。

操作方式

攝影機手勢與表情

MediaPipe 讀取鏡頭影像，偵測雙手位置、握拳與笑容，再轉成遊戲操作。

線上功能

Firebase 即時同步

Firebase Auth 提供匿名玩家身分，Realtime Database 儲存配對、對戰狀態、道具事件與排行榜。

整體架構流程

1. 玩家 打開網頁，允許瀏覽器使用攝影機。
2. MediaPipe 每一幀分析影像，輸出臉部與手部 landmark。
3. 遊戲邏輯 依據手勢、笑容、時間、訂單、桌位與盤子數更新狀態。
4. Canvas + HTML UI Canvas 繪製場景，HTML 疊加選單、HUD、排行榜與結算畫面。
5. Firebase 線上模式才同步玩家分數、配對、道具事件與排行榜。

前端怎麼運作

畫面層

Canvas 繪圖

game-canvas 負責背景、顧客、餐點、桌面、提示與遊戲場景；hand-canvas 專門畫玩家手部。

UI 層

HTML 疊加介面

title-screen、level-select-screen、result-screen、leaderboard-screen 等元素負責選單與結算。

主迴圈

requestAnimationFrame

gameLoop() 每幀偵測鏡頭、更新物理、處理顧客耐心、操作邏輯，最後重畫畫面。

視覺辨識

MediaPipe Tasks Vision

FaceLandmarker 判斷笑容接待客人，HandLandmarker 判斷手的位置與握拳狀態。

物理互動

Matter.js

桌面清理使用 Matter.js 的剛體與碰撞，讓垃圾、盤子、叉子等物件能被手部碰撞推動。

本機儲存

LocalStorage

42PastaSave 儲存關卡星等，42PastaNickname 儲存玩家稱號。

前後端如何串聯

這個專案沒有自己寫 Node.js、PHP 或 Python 伺服器。它採用 Firebase 當後端服務，所以前端 JavaScript 會直接透過 Firebase SDK 讀寫雲端資料庫。

身分驗證
signInAnonymously() 讓每位玩家取得一個 Firebase UID，作為線上配對與排行榜的玩家 ID。
配對佇列
玩家進入線上模式後寫入 queue/{playerId}。如果找到等待中的玩家，就建立一筆 matches/{matchId}。
即時對戰
matches/{matchId}/players 同步雙方稱號、分數、負評、已完成狀態與道具欄。
道具事件
matches/{matchId}/events 儲存道具攻擊事件，對手端用 onChildAdded() 監聽並套用效果。
排行榜
leaderboardStats/{playerId} 統計勝敗、最高分、平均分與總場次，排行榜以勝場與分數排序顯示。

遊戲狀態與玩法流程

大狀態 macroState

控制現在是載入、標題、輸入稱號、配對、關卡選擇、遊戲中、結算或排行榜。

小場景 microLocation

控制玩家所在區域，例如櫃台、用餐區、廚房、洗碗區與清桌區。

料理狀態 cookState

控制從放麵、煮麵、裝盤、加配料、攪拌到送餐的料理流程。

單人模式流程

載入模型與攝影機後進入標題畫面，玩家輸入稱號並選擇單人模式，接著選關、接待顧客、料理、送餐、清桌、洗碗，時間到後計算分數與星等。

線上模式流程

玩家輸入稱號後進入 Firebase 配對。配對成功後雙方同時倒數開始，在限定時間內各自遊玩，分數與道具事件即時同步，最後送出排行榜資料。

AGENTS.md

project-overview.html

如何執行與注意事項

建議執行方式

因為遊戲需要攝影機權限與外部 CDN，建議用本機伺服器或 HTTPS 開啟 index.html。若直接用檔案開啟，瀏覽器可能阻擋攝影機。

網路需求

MediaPipe 模型、Matter.js、Firebase SDK 都從網路載入。離線時遊戲可能無法完成初始化，線上對戰與排行榜也無法使用。
